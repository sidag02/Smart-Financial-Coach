# FR-3 Categorization — Launch Round Results

Oct 1, 2026 (test results and promotion added Oct 2) · @Sidd · Milestones 4 and 5 of FR-3 Transaction Categorization — Feature Design ("Trimmed for launch")

## Summary

- **Every launch variant ties.** On validation, the four calibrated linear candidates score 0.503–0.512 macro F1 on unseen merchants, and every paired difference from the leader has an interval spanning 0 (about −0.05 to +0.03). Neither a larger embedding model (bge-base) nor wider n-grams (1–5) measurably helps unseen merchants under this data and noise. On known merchants all are at 0.965–0.969.
- **Calibrating per familiarity group matters for FR-5.** One calibrator for all strings gives the same categories, but its confidence on unseen merchants is much worse: Brier 0.242 vs 0.229, and confidence ≥ 0.9 is right **61%** of the time instead of **92%**. The per-group design stays.
- **bge-base is the decision rule's winner.** It ties on F1, has the best-calibrated confidence on unseen merchants (Brier 0.216 vs 0.224 for the runner-up), and costs about 2.8× the batch time of bge-small (4.5 s vs 1.6 s per 10k transactions, `latency_batch_ms`, about 2,200 vs 6,200 transactions per second in one process) and twice its ONNX memory. Latency was a promotion gate when the round ran; it no longer is (decision Oct 2, 2026), because categorization runs batched on ingestion, so the cost is a cluster-sizing question.
- **Promoted: bge-base (`20_linear_base`), version `3f0ccc82-2f0e60a6`.** On the test sets, scored once, it passes both gates: known-merchant macro F1 0.970 against 0.90 and the keyword baseline's 0.461. All test users: 0.796. Unseen merchants: 0.462 (0.40–0.55).
- **Known issue, shipped knowingly:** on unseen merchants the model's fallback guess is Travel. It calls 30% of unseen-merchant transactions Travel, nearly all wrongly, at confidence about 0.5. The likely cause is the injected label noise in the shipped model's training ([Test results](#test-results-and-promotion-oct-2-2026)).
- **The absolute numbers are lower than in the POC because of label noise.** Every run trains under the kept 2% uniform label noise (FR-3 §5): 39% of Travel's training labels are wrong. The POC's noise-free unseen F1 was about 0.64.

## Setup

- **Data:** the default dataset (schema 3). Validation folds hold out the 169 holdout-eligible merchants of train users (3 folds), plus a 10% seen-merchant row sample per fold. Ranking used no test data; the test sets were scored once afterwards, by `finalize`.
- **Candidates:** calibrated (`method: auto`, per familiarity group unless stated) linear text models, C fixed at 1.0 (round 1's choice), 2% uniform label noise on training rows. Configs: `configs/experiments/categorization/launch/`.
- **Rule:** the FR-3 decision rule. Eligible = validation known-merchant macro F1 ≥ 0.90 and above the keyword baseline. Ranked by validation unseen-merchant macro F1, ties against the leader by paired merchant bootstrap, tie-breakers in order.
- **Time:** 37 minutes for all seven configurations (baselines about a minute together; bge-small 7.5 min; bge-base 13.8 min).

## Findings

1. **Text representation:** bge-base vs bge-small is +0.009 unseen F1, well inside the measured noise floor (±0.015) and the paired interval (−0.049 to +0.028). Its confidence is a little better (Brier 0.216 vs 0.229, accuracy at 0.9: 97% vs 92%), at twice the training time and 1.7× the cold latency. Following the trimmed plan, larger embedding models are not tried, since bge-base didn't win.
2. **N-gram range:** 1–5 vs 2–4 changes nothing measurable (0.504 vs 0.503 unseen, 0.965 vs 0.968 known).
3. **Calibration grouping:** one calibrator is clearly worse for unseen merchants (above). The cross-validated method choice, reported per run under `held_out.*` in MLflow, is the other half of round 7.
4. **Misallocated spend:** about 26–27% of unseen-merchant spending dollars land in the wrong category for every candidate, against 45% for the keyword baseline. This is the number the dashboard feels for brand-new merchants, and the case the feedback loop (Technical Design, "Learning from user feedback") is meant to fix.
5. **The keyword baseline's confidence is the best calibrated on unseen merchants** (Brier 0.197). It is right less often but knows it. It's a reminder that Brier rewards honesty about uncertainty, not accuracy alone.

## Decision: serving cost is reported, not gated (Oct 2, 2026)

The round showed the rule ranking first a run that failed the 5 ms per-transaction latency gate (bge-base, 5.05 ms p95 cold on a laptop; the same code measured 8.95 ms on a CI runner).

- **Decision:** categorization runs **on ingestion, in batches** across users. Per-transaction serving time is a cluster-sizing cost, not a reason to reject a better model, so the latency gate is removed from promotion.
- **Cost still breaks ties:** the second tie-breaker is now batch cost (`latency_batch_ms`, a fixed 10k-row batch) instead of single-call p95.
- **What gets measured instead:** throughput, pod memory and cold start on the serving profile, as deployment sizing in milestone 5 and the serving design.
- **The order doesn't change:** Brier already separates every tied run, so bge-base stays first and is now promotable.

**A rule change made after seeing results.** It was decided after the launch round's numbers were known, including bge-base's. It uses no test data, and its reason is the serving pattern, not any run's score. But a document meant to show disciplined selection should say so plainly. Review measurements support it independently: one cold p95 varied 17% across 8 repeats on the same machine (3.17–3.73 ms for bge-small), so a hard millisecond cut near 5 ms would have flipped with reruns.

The FR-3 design ("Metrics and why", point 7) and the Technical Design (compute timing, selection criteria) record the decision.

## Test results and promotion (Oct 2, 2026)

`sfc-experiment finalize` scored the decision rule's top three, and the three baselines, on the test sets once (table above). Nothing was re-ranked on these numbers.

1. **bge-base passes the gates and was promoted** as the rule's winner (`sfc-model promote`, run `000ef7d3`). Its model file is in the GitHub Release `categorization-3f0ccc82-2f0e60a6`; the manifest, `PROMOTED` and the promotion log are committed.
2. **Unseen merchants: the finalists don't beat the keyword baseline on test.** 0.462–0.472 against keyword's 0.482, with overlapping intervals (0.39–0.59). On validation they had led it, 0.50–0.51 against 0.425. With 58 holdout merchants, both readings are within noise; neither is a gate. The models still misallocate much less unseen spend (36% of dollars against keyword's 49%), and keyword's refund accuracy is 0.03.
3. **All test users: exact-string lookup scores higher** (0.874 against 0.796). Most test-user transactions are at strings seen in training, and a per-string majority vote is barely affected by 2% uniform noise. Logistic regression with balanced class weights is affected a lot. Lookup is useless on unseen merchants (0.066), so it isn't a candidate. `Lookup(fallback=model)` is the deferred round 6 composition.
4. **Travel is the fallback guess for unfamiliar merchants.** Running the promoted model on the whole default dataset (`sfc-model predict`) gives 27,271 Travel predictions against 2,851 true Travel transactions. At holdout merchants, it calls 23,191 of 78,073 rows (30%) Travel, 23,018 of them wrongly, at average confidence about 0.5. At known merchants, accuracy is 0.983 for train and test users alike. The likely mechanism: uniform 2% noise moves the same number of wrong labels into every category, so 39% of Travel's training labels are wrong. Balanced class weights then give that rarest class the most weight, and the model learns Travel as "an unfamiliar string". The shipped model is trained under the same noise as the experiments.
   - **Decision (owner, Oct 2, 2026, after seeing these results):** ship bge-base as the rule's winner. The cold-start model only needs to be decent, and the low confidence routes many of these rows to FR-5 review. Feedback retraining is the remedy. Training the shipped model without the injected noise was considered. It would have needed a second, recorded round of test scoring.
5. **Confidence on known merchants is under-confident, not over-confident.** Known-merchant ECE is 0.153 on test (0.139 on validation). Only 33% of rows reach confidence 0.9, and those are 100% right. Cross-validated Brier chose no calibration for familiar strings, so the raw model's flattened probabilities pass through. FR-5 should set its threshold from the reliability curve, not assume 0.9 means 90%.
6. **Serving cost, measured** (`sfc-model predict`, default dataset, laptop CPU, one process): 1,098,595 transactions in 90 s, about **12,200 rows per second**. Peak memory is 2.1 GB at 20k-row batches (the default) and 7.2 GB at 100k, at the same throughput. Model load takes 0.6 s once the file is downloaded.
